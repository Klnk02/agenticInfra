# Agent Infra 系统课：在有限资源上运行、记住和恢复许多 Agent

目标岗位是维护 **agent 执行平台**的工程师，不是开发某个 agent 应用。毕业题是：**两个租户同时提交长任务，任务会扇出、等工具、取跨会话记忆，还会跨 worker 恢复。模型服务的 KV 容量固定。你能指出瓶颈、改一条策略，并用同一批任务证明改善没有牺牲正确性吗？**

**从这里开始：** [首课：四个 token 的 KV 到底省了什么](05-KV缓存与推理调度.md)。15 分钟、普通 CPU、无模型权重或云账号。已有基础就直接做出口题。以后从[进度与交接](00-当前进度与交接.md)接续。

| 你关注的方向 | 这门课真正要学的东西 | 动手或验收 |
|---|---|---|
| Agent Runtime / Harness | 请求、run、step、attempt 的所有权；模型/工具适配边界；工作进程可以销毁而逻辑任务不丢 | [双账本事故](02-首课与实验手册.md)和[系统路线 W1](01-路线与验收.md)；不是做工具集合 |
| 推理服务与 KV cache | causal attention、prefill/decode、KV 容量、前缀复用、页回收、批次 token 预算 | [真算注意力 + 有限页池](05-KV缓存与推理调度.md)，定点读 vLLM |
| Memory 系统 | 持久事实、异步索引、namespace、版本、TTL、删除可见性；召回质量和新鲜度 | [真实 SQLite + FTS5](06-Memory与Context.md)；不是给聊天接一个向量库 |
| Context Engineering | 把一个状态版本编译为有预算、可复现的模型输入；同时衡量事实保留和前缀复用 | [同一记忆，两种输入布局](实验/context_trace.py)；不教提示词话术 |
| Durable Execution | checkpoint、已提交意图、回放、幂等与所有权；区分重试与重新采样 | [故障注入](02-首课与实验手册.md)、[LangGraph 对照](03-开源源码导读.md) |
| 长程任务执行 | 跨进程/跨版本恢复、历史增长、持久计时器与等待、取消后的对账 | [一万条事件的恢复](07-长程执行与多Agent调度.md)，区分 snapshot 与换一段历史 |
| 多 Agent 调度 | 跨 run、跨租户的 DAG、fan-out/join、背压、公平和资源预算；与推理引擎的 token 调度分开 | [双租户调度器](实验/dag_scheduler.py)：尾部租户等待与整批吞吐的取舍 |
| Sandbox / Agentic RL | 两项都只保留接口：前者返回执行事实，后者消费带来源和终止原因的 rollout | [边界说明](01-路线与验收.md)。不重复学隔离实现、奖励设计或训练算法 |

**节奏：** [6 周路线与出口题](01-路线与验收.md)，建议每周约 3 小时；[系统源码导航](08-系统源码与毕业验收.md)只看能检验当前假设的函数。旧的单任务 harness 材料保留作[按需选读](附录-单任务可靠性训练.md)，不再占前两周。

**不在目标内：** 聊天产品、客服/写作流程、角色设定、业务连接器、提示词技巧、框架 API 汇编。所有任务名只是合成负载。课程不以调通一个应用为验收，也不把 CPU 模拟结果当成 GPU 性能数据。
