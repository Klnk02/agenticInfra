# Agentic Infra 工程师学习路径：Agent Runtime 与 Harness

**毕业题：外部工具已经发布了一个构建，但 agent 在收到回执前退出了。接手的 worker 应该继续、重试、停止，还是问人？它凭什么知道？** 这门课从一次模型调用追到这道题，再用评测验证修复没有掩盖新的错误。目标不是记住三个框架的 API，而是能为一个长任务 agent 设计执行契约、写回归、解释故障并判断能否上线。

**第一次只做一件事：** 打开 [第 1 课](02-首课与实验手册.md)，先预测两种中断留下的记录。15 分钟可做完第一轮；不需要 API key、Docker 或 GPU。日后从[进度与交接](00-当前进度与交接.md)恢复。

## 先把三个词分开

| 本课用词（工程分工，不是行业统一定义） | 要负责的决定 | 在哪里看见它 |
|---|---|---|
| **Agent harness（模型的工作环境与交互循环）** | 给模型看哪些消息、可用哪些工具、什么时候把输出认作有效动作、什么时候停 | [一轮工具调用](实验/harness_turn.py)：流断在半截，工具调用数必须为 0 |
| **Agent runtime（运行与恢复）** | run 属于谁、哪些事实已经持久化、哪些步骤可重做、预算或取消后怎样收尾 | [可中断 runtime](实验/runtime_lab.py)：本地动作记录和外部发布账本属于两个提交域 |
| **Evaluation harness（评测装置）** | 固定任务和环境、收集外部证据、对结果打分，而不是相信最终文本 | [同题对照](实验/paired_eval.py)：`finished`、业务成功和不可评分各自统计 |

它们可以住在同一个进程。**Sandbox 在这张图里只是工具执行后端**：提供执行结果、超时/取消与副作用是否可确认的信号。课程不讲隔离实现，不接公司机器。已经做过 `model → tool → observation` 的读者，不必再搭一遍环境；直接用出口题跳级。

## 路线图（建议 6 周 × 每周 3 小时；按证据而非日历过关）

| 周 | 这一周只解决的问题 | 交付物 |
|---|---|---|
| 1 | 模型说“我已完成”与工具真的做了，证据各在哪？ | 一次 turn 的责任链及一个拒绝分支 |
| 2 | 上下文不够、流中断或预算耗尽时，如何不产生半个动作？ | 可复跑的消息配对/截断回归 |
| 3 | 请求丢了还是回执丢了？重复提交是谁阻止的？ | 双账本故障矩阵与本人写的一条恢复测试 |
| 4 | 并行节点一个失败后，图执行器究竟重做哪部分？ | 真实 LangGraph 探针 + 源码断言映射 |
| 5 | 慢工具占满 worker、取消和迟到回执竞态时，谁还能写？ | 单租户限流和过期 worker 的反例/修复 |
| 6 | 运行都显示完成，为什么不应该上线？ | 配对回归、独立 scorer、上线决定与局限说明 |

**省时原则：** 每课只记一条能推翻你预测的证据。如果能在陌生条件下画出责任方、预测输出并写出失败断言，就跳过同层教程；把时间留给恢复、上下文和评测。结课不要求造通用框架，但要求你能从一条失败轨迹定位应该改模型交互、执行策略还是评分器。
